# Feature context: f-know-how-much-to-trust-it

Intent: A surfer sees a confidence level on every row and taps it to read why in plain Spanish,
for example that the models agree on size but split badly on period, so if it is the 15 second
swell it is on.

Workspace opened 2026-08-09 from the epic row (`docs/epic/surfs-up-panama/epic-delta.md`, row
`F-KNOW-HOW-MUCH-TO-TRUST-IT`, status `pending` at open) and the dispatch brief. This is the
DOCS-ONLY workspace creation: no acceptance test, no step definition, and no production code
exists for this feature yet. Each slice's tests are written Just In Time when that slice legally
enters DISTILL (`HANDOFF.md` §1, DISTILL row). `BUILD-ORDER.md` and `plan-cluster-*.md`, which the
sibling workspaces cite for their contended-files tables, exist neither on this worktree's disk
nor in any git ref of this repository (verified against all 251 historical paths; not gitignored),
so every contention record below derives from the dispatch brief and `HANDOFF.md` §10 and must be
re-checked against BUILD-ORDER where it actually lives before integration.

**This is a delta on a shipped surface.** The keystone's slice-07 already ships the day-one
confidence display: `src/scoring/confidence.ts` (full 05 §6 engine contract plus
`CONFIDENCE_LEVEL_WORD_ES` and `confidenceReasonEs`), `src/components/Confidence.astro` (zero-JS
`<details>` disclosure), the one-line mount at `src/components/RankedList.astro` line 89, the
property tests in `tests/unit/confidence-reason-copy.test.ts`, and the amended charter
`EXP-daily-call-with-permanent-receipts-7` (commits `f87fb3e`, `d9a44b5`, `4f9dc00`, `5d58933`,
`a093e4c`, `ef481f6`). That charter's own line 38 routes the rest here: "Deferred, not this slice:
confidence that folds in real spread semantics and the track record
(F-KNOW-HOW-MUCH-TO-TRUST-IT)." `HANDOFF.md` §5 adds "slice-07 needs rewording when it lands" and
settles, not to be relitigated, that zero beach reports exist and day-one confidence is model
agreement.

Not missing, and deliberately not claimed here: C_track and C_fresh machinery already ship in the
engine with the honest launch inputs (track null, factor 1, `track_state: "unverified"`; no report
ever, `c_fresh: null`, excluded). Their real inputs arrive as data from the learning lane and the
report features. This feature's obligation is that the reason copy renders from those inputs
instead of hardcoding today's truth, so the copy flips itself the day the inputs change.
